# 定义 v2 首发产品边界

- 状态：已决定
- 类型：Grilling
- 阻塞：无
- 解锁：确认信息架构与页面模型、确定 API 与异步操作契约

## Decision question

哪些旧能力必须进入 v2 首发闭环，哪些能力明确延后或只保留 CLI？

## Known constraints

- 网站必须是主要入口。
- 旧项目已有扫描、筛选、平台选择、安装预览、来源更新、冲突比较、备份恢复、原创/派生和说明文档能力。
- 首发不能为了“功能齐全”而保留空壳入口。

## Options to examine

- 最小闭环：扫描、浏览、启用、安装、来源更新、记录与恢复。
- 完整迁移：额外包含来源添加/删除、原创/派生、Profile 编辑、说明文档编辑和冲突 diff。
- 分层发布：首发闭环 + 高级功能按里程碑迁入。

## Resolution

采用分层发布，但首个可用版本必须覆盖完整日常闭环：

- Skills：浏览、搜索、筛选、详情、扫描、启用范围、保存选择、安装预览与应用、原创与派生入口。
- 来源：健康状态、脏文件解释、更新检查、安全来源的部分更新、启停、添加与详情。
- 记录：事务、更新报告、备份与恢复预览。
- 高级 Profile 编辑继续由后端兼容，但首个界面只展示当前 Profile；后续再提供专用编辑器。
- Skill 长说明以详情中的文档视图起步，不在首版内置完整 Markdown 编辑器。

所有没有真实实现的入口必须隐藏，不放置占位按钮。
