# 确定安全事务与权限边界

- 状态：已决定
- 类型：Grilling
- 阻塞：无
- 解锁：确定 API 与异步操作契约、确定测试接缝与验收矩阵

## Decision question

哪些操作必须预览、确认、备份和记录，哪些只读或可重建操作可以直接执行？

## Known constraints

- 安装、更新、删除、来源策略与恢复会改变本地状态。
- 扫描主要重建 Catalog，但仍可能覆盖生成文件。
- 来源中的本地改动不得被自动删除、stash、commit 或覆盖。
- 一次性 preview token 与状态指纹是旧系统已验证的安全基础。

## Decisions to make

- 操作风险分级与一致的 UI 容器。
- token 生命周期、重复消费、过期与重新检查语义。
- 批量操作中的部分可执行与原子回滚策略。
- 后端允许访问的路径与拒绝越界规则。
- 备份保留、恢复范围和用户级目录保护名单。

## Resolution

- 只读：状态、列表、详情、Catalog 新鲜度检查可直接执行。
- 可重建：扫描可直接执行，但必须显示运行状态和差异结果，不修改 Skill 内容。
- 配置写入：保存平台选择可直接保存到受管 Profile，并记录事务；与平台实际安装明确分离。
- 外部或批量写入：安装、更新、恢复、来源启停/删除必须 Preview → 用户确认 → Apply。
- Preview token 绑定状态指纹、只能消费一次；过期后回到检查步骤。
- 更新只把 `fast-forward && clean` 或 `self-managed` 来源纳入可应用集合；脏、分叉、缺失来源保留为阻塞说明，但不阻止安全来源。
- 服务只接受本机 Host/Origin，不暴露任意路径读取接口。
