# writing-for-agents

> 写给 agent 读的文档（skill、`AGENTS.md`/`CLAUDE.md`、指针指向的文档）的写作参考——让 agent 每次跑同一套流程。

## 1. 一句话理解

`writing-for-agents` 是一份**元技能**：教你怎么写"agent 会读的文档"。它不针对某个产出，而是给出一套让文档"可预测"的杠杆——agent 每次跑同一套流程，而不是产出相同结果。

## 2. 它解决什么问题

给 agent 写文档和给人写文档是两回事：一个多出来的词、一个弱措辞的指针、一句"别做 X"的禁令，都会在 agent 每次运行时放大成偏差。本 skill 把这些偏差源系统化，教你用最少的 token 获得最可靠的触发与执行。

## 3. 核心心智模型

**上下文指针（context pointer）**：agent 上下文里一条引用，点名某段上下文外材料并编码"何时去取它"的条件。skill 的 description 是一个指针，`AGENTS.md` 里指向某文档的一行也是同一个东西。**措辞决定触发的可靠性**——好目标配弱措辞 = 偏差 bug，先磨措辞。

**两种负载**：

- **上下文负载**：常驻材料对窗口的消耗（`AGENTS.md` 行、skill description）。
- **认知负载**：人对"有哪些文档、何时用哪个"的负担——人是索引，这不是要最小化的成本，而是人类能动性的代价。

**信息层级（the ladder）**：一条从"agent 多快需要它"排的阶梯——① 文件内步骤 → ② 文件内参考 → ③ 披露参考（推进到单独文件、靠指针触发）。**渐进披露**是往下走、让顶层可读；**共置**是文件内配套（一个概念的定义/规则/警示放一个标题下）；**蔓延**是失败态（太长，即使每行都鲜活）——药方是阶梯：披露 + 按分支/序列拆分。

**步骤 + 完成标准**：每个步骤结尾要给一个**完成标准**（done 的判据）。两个杠杆——**清晰**（能区分做完没做完，含糊边界诱发"过早完成"）与**要求**（"每个修改过的模型都核对过"比"产出清单"更费力，驱动 legwork）。最强的标准既可核验又穷尽。

**领先词（leading word）**：一个已经活在模型预训练里的紧凑概念（`lesson`、`fog of war`、`tracer bullet`），当作 token 反复用，累积分布式定义，用最少的 token 锚定一整个行为区。优先用已有词（自造词不招募先验，得付定义 token 的代价）。它锚定两处：正文里的**执行**、指针里的**唤起**。

**否定是失败态**："别想大象"，大象就全是内容——禁令把被禁行为拖进上下文，让它更可用而非更不可用。要**正面表达**（写"写单行注释"，不说"别写多行注释"）。

**修剪**：每个含义单一事实源；环境也是事实源（`package.json` 脚本、config、目录、`--help`），文档重述它就是 cache；逐行查相关性；逐句找 no-op（删掉整句而非删词）。

## 4. 一次典型运转

写一个 skill：先读 `SKILL-MECHANICS.md`（frontmatter、调用方式、路由 skill）→ 决定每块内容在信息层级上的位置（步骤在文件内、规则在文件内参考、可选分支披露出去）→ 每个步骤给清晰且够要求的完成标准 → 用领先词替换三处重复的表述 → 正面表达而非禁令 → 逐行修剪。

## 5. 何时用 / 何时不用

**用**：创建/编辑 skill，或改 `AGENTS.md`/`CLAUDE.md`。

**不用**：写给人读的普通文档。

## 6. 依赖与网络位置

- 附属：`SKILL-MECHANICS.md`（skill frontmatter、调用、路由）。
- 是这套 skill 集的"元语言"，几乎每个 skill 的写法都受益于它。

## 7. 易错点与坑

- **否定式禁令**：把"别做 X"改成"做 Y"。
- **好目标配弱措辞的指针**：先磨指针措辞，再考虑内联。
- **在信息层级上放错位置**：可选分支的内容内联进正文，会把顶层堵死。
- **缓存环境可查的东西**：`package.json` 脚本、config 别在文档里重述。
