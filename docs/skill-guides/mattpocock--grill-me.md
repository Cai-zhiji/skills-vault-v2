# grill-me

> 一轮无休止的访谈，用来打磨一个计划或设计。

## 1. 一句话理解

`grill-me` 就是一个别名：跑一轮 `/grilling` 会话。它适合**没有完整项目文档、但需要先把决定想清楚**的场景——纯访谈，不写任何文件。

## 2. 它解决什么问题

当你有一个模糊的计划/设计，又不想（或不能）把它落进某个代码仓库的 `CONTEXT.md`/ADR 时，`grill-me` 提供一个纯粹的拷问入口：一轮轮把决定问清，直到你和 agent 达成共同理解。

## 3. 核心心智模型

与 `grilling` 完全相同：把讨论映射成**设计树**，每轮只问"前置已定"的前沿问题，每个问题附推荐答案；回答推进前沿，直到前沿为空、没有静默假设。区别只在**是否落盘**——`grill-me` 不落。

## 4. 一次典型运转

用户说"我想清楚这个方案"→ 起 `grilling` 会话 → 逐轮问前沿 → 收敛到共同理解 → 停（结论交给后续的 `to-spec`/`implement` 或项目文档，而不是继续问）。

## 5. 何时用 / 何时不用

**用**：需求模糊、要澄清目标/约束/取舍；有多个可行方向要暴露分歧；想在实现前形成双方认可的理解。

**不用**：方案已明确、只需执行小任务；需要直接改文件/跑命令/部署（那是执行不是决策）。

## 6. 依赖与网络位置

- 依赖 `grilling`（底层对话原语）。
- 是 `grill-with-docs` 的"不落盘"孪生。

## 7. 易错点与坑

- **把澄清当执行**：它只问，不实现。
- **扩散成无穷访谈**：每轮都该让状态更清楚，不是把问题越问越多。
