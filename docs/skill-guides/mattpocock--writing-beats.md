# writing-beats

> 写作·开发（exploit）：把原始素材组装成一段"节拍（beat）"之旅，每个术语都要先铺垫（ground）才能被后面的 beat 倚靠。

## 1. 一句话理解

`writing-beats` 是"写作三件套"里**成文的那一步**：给定一堆 raw material（explore 已完成、素材堆固定），用"节拍"为单位逐拍推进文章——每拍只做一个动作，且只能倚靠已经铺垫过的概念。

## 2. 它解决什么问题

从素材到文章，最常见的失败是**概念没铺垫就跳用**，读者掉队；或者**一次写太多**，写成"五个段落 + 三个小标题"的假 beat。`writing-beats` 用"grounding（铺垫）"约束 + "一次一拍"的节奏，把这两件事根治。

## 3. 核心心智模型

**Grounding（铺垫）**：每个**概念**都要先铺垫，后面的 beat 才能倚靠它。铺垫有两种方式——**Prerequisite**（读者进门就懂，开场定死）或 **Introduced**（某个 beat 建立它，之后所有 beat 都能用）。单位是"概念"而非"它的词"——一个 beat 可以倚靠读者缺的**想法**，即使没用行话。

**每个 beat 做两件事**：它**要求**已铺垫的概念，并**铺垫**新的。维护一张"已铺垫清单"，每拍落地就更新。

**Beat 是一步，不是一个章节。** 它做一个动作（布景、落一个点、提个问、插个旁白、转个角度）就停，停在"下一拍能转向"的位置。一个 beat 可以是一句，也可以是一段小插图/论证/例子——但"五段 + 三个小标题"是两拍粘在一起，要拆。

**关键杠杆**：什么做成 prerequisite、什么在文内铺垫——开头上游要太多会挡掉没基础的读者，铺垫太多会让开头淹死在定义里。开场时和用户定，之后每遇"诱惑 beat 需要没铺垫的概念"就重访。

## 4. 一次典型运转

1. 定 prerequisite（读者进门懂什么）。
2. 从素材写 2–3 个候选**起拍**（每个是不同切入点，只倚靠已铺垫概念，说明各自铺垫了什么），给用户挑。
3. 用户挑一个 → **只写那一拍**到文章文件。
4. 重读文件 → 提供 2–3 个候选**下一拍**（从当前已铺垫集合可达，说明各自铺垫什么）。
5. 循环 3–4 直到自然收尾。

**写作节奏**：一次只 append 一拍，绝不超前写；每次写前从磁盘重读，绝对保留用户编辑；用户改前拍就让其影响后续；"重写那拍/回去试另一拍"就原地改、其余不动。

## 5. 何时用 / 何时不用

**用**：有一堆 raw material 要写成文章、且享受逐拍控制时。

**不用**：还在挖掘素材（用 `writing-fragments`）；要一段段成文而非逐拍（用 `writing-shape`）。

## 6. 依赖与网络位置

- 是 mattpocock"写作三件套"（fragments → shape/beats）中 exploit 的一支。
- 与 `writing-shape` 同属 exploit，但单位是"拍"而非"段"。

## 7. 易错点与坑

- **跳用未铺垫概念**：这是旅程唯一不能做的动作。
- **一次写多拍**：多段多小标题的"beat"要拆开。
- **写前不重读文件**：会覆盖用户编辑。
- **起拍/下一拍不说明"各自铺垫了什么"**：用户靠这个看路径会开往哪。
