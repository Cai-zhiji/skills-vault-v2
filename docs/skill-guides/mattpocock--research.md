# research

> 派一个后台 agent 针对某个问题调研高可信一手来源，把结论写成仓库里的 Markdown 文件。

## 1. 一句话理解

`research` 是把调研工作**委托给后台 agent**：你继续干别的，agent 去读官方文档、源码、规范、一手 API，把带来源引用的结论写成一个 Markdown 文件，放在仓库已有的笔记约定位置。

## 2. 它解决什么问题

调研是耗时且可并行的"阅读苦力"。如果前台 agent 自己啃文档，会阻塞整个会话；如果交给没有约束的子 agent，又可能拿二手转述当一手来源。`research` 把"后台并行 + 只信一手来源 + 逐条引用"钉成一条纪律。

## 3. 核心心智模型

**一手来源（primary source）是唯一可信来源。** 官方文档、源码、规范、first-party API——不是别人对这些东西的二手转述。每条结论都要追回到"拥有它"的源头。

## 4. 一次典型运转

用户说"查一下这个库的 API 现在怎么用"：

1. 起一个后台 agent。
2. agent 针对问题读一手来源。
3. 把每条结论连同来源引用写进一个 Markdown 文件。
4. 存到仓库已有的笔记位置（无约定就放个合理处并说明）。

## 5. 何时用 / 何时不用

**用**：想调研一个主题、收集文档/API 事实、把阅读苦力委托给后台。

**不用**：结论需要你当场参与判断、无法并行化的工作。

## 6. 依赖与网络位置

- 是 `wayfinder` 的 `research` ticket 类型的执行原语（AFK 子 agent）。
- 无硬依赖；产物落仓库笔记位置。

## 7. 易错点与坑

- **拿二手转述当结论**：必须追到一手来源，否则调研失去可信度。
- **不逐条引用**：结论和来源要一一对应，否则无法回查。
- **产物位置随意**：要匹配仓库既有约定。
