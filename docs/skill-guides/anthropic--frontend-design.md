# frontend-design

> 打造有辨识度、有意图的 UI 视觉设计：美学方向、排版、避开"AI 默认脸"。

## 1. 一句话理解

`frontend-design` 让你像**一家小工作室的设计主管**一样做 UI：给每个 brief 一个"不可能和别家搞混"的视觉身份，做刻意、有观点、特定于该 brief 的配色/排版/布局选择，并承担一个能自圆其说的审美冒险。

## 2. 它解决什么问题

AI 生成的设计现在聚类成三种"默认脸"（暖米色+衬线+赤陶点缀 / 近黑+亮酸绿或朱红 / 报纸式排版），不管主题是什么都长这样。本 skill 教你识别并避开这些默认，做出**为这个 brief 而选**而非"任何类似页面都会这么选"的设计。

## 3. 核心心智模型

**落地在主题上（ground it in the subject）。** 如果 brief 没钉死主题，先自己钉死：一个具体主题、它的受众、页面的单一任务。独特性来自主题自己的世界——它的材料、器物、行话。

**hero 是一篇论点（thesis）。** 用主题世界里最有特征的东西开场，别用"大数字+小标签+渐变强调"这个模板答案。

**排版承载个性**：display 和 body 字体要刻意配对，别用你任何项目都会选的那套；字重/字宽/间距要有意设。

**结构即信息**：编号/眉题/分隔线/标签要编码关于内容的真实信息，不是装饰；"01/02/03"只在内容真的是序列时才用。

**两遍工作流**：先头脑风暴一个 token 系统（4–6 个具名 hex 色、2+ 角色的字体、一句话布局概念 + ASCII wireframe、一个"签名元素"）；再对照 brief 审查——任何读起来像"通用默认"的部分就改，说明改了什么、为什么。确认相对独特后才写代码。

**克制与自我批判**：把勇气花在一处（签名元素），其余安静克制；自建到"质量底线"（响应式到移动端、可见键盘焦点、尊重 reduced motion）；边建边自评、截图。

## 4. 一次典型运转

1. 钉主题（brief 没给就自己定并声明）。
2. 头脑风暴 token 系统（色/字体/布局/签名）。
3. 对照 brief 审查相对独特性，改掉"默认脸"部分。
4. 按修订计划写代码，每个颜色/字体决策都从计划导出。
5. 自评 + 截图，克制修饰。

## 5. 何时用 / 何时不用

**用**：建新 UI 或重塑现有 UI，需要美学方向、排版、避免模板化默认。

**不用**：纯功能后端、不涉及视觉设计。

## 6. 依赖与网络位置

- 是 `anthropic` 来源的视觉设计技能。
- 与 `web-artifacts-builder`（用 React/Tailwind 建复杂 artifact）互补——本 skill 管"视觉怎么设计"。

## 7. 易错点与坑

- **落入三种 AI 默认脸**：暖米色+衬线、近黑+酸绿、报纸式——它们不是选择，是默认。
- **签名元素不签名**：勇气要集中一处，别到处花哨。
- **CSS 选择器优先级打架**：`.section` 和 `.cta` 类选择器相互抵消（尤其 section 间 padding/margin）。
