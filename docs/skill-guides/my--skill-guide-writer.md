# skill-guide-writer

## 1. 一句话理解

这是一个把原始 `SKILL.md` 重写成可直接阅读、可在网页中展示的中文功能说明文档的文档生产 Skill。

## 2. 它解决什么问题

Skill 的原始文件通常更像给 Agent 执行的规则集：触发条件、限制、命令和内部术语分散在长文中。直接把 description 放进目录，只能帮助检索，无法说明它为什么存在、怎样运转、什么时候不该使用。这个 Skill 解决的是“目录能找到，但读者仍然不理解”的问题：它把原文中的执行逻辑重新组织成一篇面向人的说明，同时保留原始路径和 commit，方便回查。

## 3. 核心心智模型

它的核心不是翻译，而是“从执行规则提炼使用心智模型”。每篇文档都要回答一条完整链路：

```text
原始 SKILL.md → 关键问题与核心概念 → 典型运转场景 → 使用边界 → 可回查出处
```

其中 `## 3. 核心心智模型` 是质量分水岭。比如一个调试 Skill 应该提炼出“变红回路”，一个架构 Skill 应该提炼出“深模块”；读者先理解这个概念，再理解流程和限制。因而不能只扫描标题、函数名或附属文件，也不能逐段翻译原文。输出必须是中文重述，英文术语、命令、代码和示例只在需要精确调用或回查时保留。

## 4. 一次典型运转

单篇制作从用户给出的 Skill 名称或完整 ID 开始。先在 `catalog/catalog.json` 找到唯一条目，确认它的 `id`、`name`、`path` 和 `source_commit`；再完整阅读该目录下的 `SKILL.md`，不能只读 frontmatter 的 description。接着以固定顺序重述为八个部分：定义它是什么，解释它解决的痛点，提炼核心心智模型，讲一遍端到端使用场景，划定何时使用与何时不用，说明依赖和同名冲突，记录易错点，最后写入出处信息。

文件必须写到：

```text
docs/skill-guides/<source>--<skill-name>.md
```

例如 `my/skill-guide-writer` 对应当前文件。写完后检查正文是否正好包含 8 个二级标题，并确认 `## 8. 出处` 中的 commit 前 7 位与 catalog 一致。

批量制作时，读取 catalog 的全部 `skills`，按 `my`、`mattpocock`、`academic`、`anthropic` 的来源顺序逐篇执行相同流程；最后核对说明文件数量、路径映射和是否存在多余文件。批量过程可以覆盖已有文档，因此执行前要确认用户确实要求重写，而不是只补齐缺失文档。

## 5. 何时用 / 何时不用

适合使用：

- 用户要求为一个指定 Skill 撰写说明、重写说明或补充中文介绍。
- 上游 `SKILL.md` 发生变化，需要重新理解后刷新对应文档。
- 用户要求批量生成或重写 `docs/skill-guides/` 中的全部说明。
- 需要让网页详情页展示“概述、流程、边界和出处”，而不是直接展示原始 description。

不适合使用：

- 只是修改 Skill 的执行规则、frontmatter 或代码实现；这属于 Skill 本身的维护。
- 只想建立目录索引或路由表；本 Skill 明确不创建总索引。
- 没有完整读取原始 `SKILL.md` 就想凭 description 生成说明。
- 需要分析脚本实现、函数调用或仓库内部代码；本 Skill 的边界是阅读 `SKILL.md` 正文，不是代码审计。

占位模板 `anthropic/template-skill` 可以采用最小说明，明确它是复制新 Skill 的模板，不要为占位内容虚构完整能力。

## 6. 依赖与网络位置

它没有必须安装的运行时依赖，也不要求访问网络。它依赖项目内的两个输入约定：

- `catalog/catalog.json`：提供 Skill ID、路径、名称和上游 commit。
- `<skill path>/SKILL.md`：唯一的主要知识来源，必须完整阅读。

输出依赖网页约定的文件命名：`docs/skill-guides/<source>--<name>.md`。该路径被 `/skills/<id>` 详情页使用，不能改名。它不与其他 Skill 产生同名调用冲突；自身可通过 Codex `$skill-guide-writer` 或 Claude Code `/skill-guide-writer` 显式调用，也可根据描述在文档维护任务中被触发。

## 7. 易错点与坑

- 把 catalog description 直接翻译成中文，会遗漏动机、心智模型和边界，属于目录摘要而不是说明文档。
- 只读 `SKILL.md` 的前几行或标题，会把真实工作流误判成单一命令；必须读完整正文。
- 把原文步骤逐条搬过来，会让读者重新阅读原文；`## 4` 应该讲清一次典型运转，而不是复制编号。
- 写成“证据目录”或文件夹地图，会偏离目标；不输出函数名、配置键、附属文件扫描表来冒充理解。
- 改动 `source--name` 文件名、一级标题或八个二级标题，会破坏网页路由、目录生成和质量校验。
- 遗漏 `## 8. 出处` 的 commit，或者使用过期 commit，会让文档无法判断是否需要重新审核。
- 批量重写会覆盖已有文档；手工维护的文档应在执行前明确保护策略，不能默认覆盖。
