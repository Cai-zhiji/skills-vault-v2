# algorithmic-art

> 用 p5.js 以种子随机与可交互参数创作算法艺术：生成艺术、流场、粒子系统，强调原创避免抄袭。

## 1. 一句话理解

`algorithmic-art` 是一套**两阶段的生成艺术方法**：先写一份"算法哲学"（一个生成艺术运动的名字 + 4–6 段宣言），再把它**表达成 p5.js 代码**（`.html` + `.js`），产出可交互的生成艺术。

## 2. 它解决什么问题

直接让 AI"画个图"容易得到模板化、无灵魂的结果。本 skill 逼出一个**原创美学运动**作为前置——先想清楚"这是一种什么样的生成美学"（涌现、噪声场、有机系统、受控混沌），再用代码实现它。这样产出的是"有观点"的算法艺术，而不是复制某位艺术家的作品。

## 3. 核心心智模型

**哲学先行，代码随后。** 两阶段：

1. **算法哲学创作**（`.md`）：给运动起名（1–2 词，如 "Organic Turbulence"），用 4–6 段写清这个美学如何通过计算过程、数学关系、种子随机、噪声场、粒子/流/场/力、参数变化与受控混沌体现。
2. **用 p5.js 表达**（`.html` + `.js`）：同一版本接收哲学，写成 **90% 算法生成 + 10% 必要参数** 的 sketch。

**批判性理解**：收到的用户输入只是**地基**，不应限制创作自由；重要的是产出原创哲学并忠实表达它。强调：算法表达、涌现行为、计算之美、种子变化。

## 4. 一次典型运转

1. 读用户输入（作灵感地基，不约束）。
2. 写算法哲学 `.md`：命名 + 宣言。
3. 用 p5.js 写 `.html`/`.js`，90% 生成 + 10% 参数。
4. 产出可交互的生成艺术。

## 5. 何时用 / 何时不用

**用**：用户要"用代码创作艺术"、生成艺术、算法艺术、流场、粒子系统。

**不用**：静态设计/海报（`canvas-design`）；复制现有艺术家作品（明确禁止，避免版权侵权）。

## 6. 依赖与网络位置

- 依赖 p5.js。
- 附属：`templates/generator_template.js`。
- 与 `canvas-design` 是"代码生成"vs"静态视觉"的孪生。

## 7. 易错点与坑

- **跳过哲学直接写代码**：会退回模板化结果，哲学是本 skill 的灵魂。
- **复制艺术家作品**：必须原创，避免版权问题。
- **参数过多**：要 90% 算法生成、10% 参数，别把生成器写成参数堆。
