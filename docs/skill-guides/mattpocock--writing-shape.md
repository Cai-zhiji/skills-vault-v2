# writing-shape

> 写作·开发（exploit）：把原始素材塑成一篇文章，逐段推进。

## 1. 一句话理解

`writing-shape` 是"写作三件套"里**成文的一支**：给定一个 raw material 文件（read-only），逐段（block）把文章塑出来——每段只能倚靠已铺垫的概念，段的形式（散文/列表/表格/引语/代码）要刻意、可辩护地选择。

## 2. 它解决什么问题

从素材到成文，最难的是"顺序"和"形式"：读者该按什么顺序听到什么？这段该是散文还是列表？`writing-shape` 用 grounding 约束顺序，用"逐段争论形式"约束表达，把文章从素材堆里一条一条塑出来。

## 3. 核心心智模型

**The loop（循环）**：

1. 通读素材堆。
2. 定 prerequisite（读者进门懂什么）。
3. 起草 2–3 个候选开头（各暗示不同 thesis/角度），逼用户选或组合——选定的开头定义文章余下要做什么。
4. 逐段生长：问"给定这个开头，读者下一步需要听到什么？"从素材堆取料，下一段只能倚靠已铺垫概念、并铺垫新的；**争论这段的形式**（散文/列表/表格/引用/代码块）并让选择可辩护。
5. 边写边 append 到文章文件，不批量。
6. 循环 4 直到用户说完成。

**Grounding**：与 `writing-beats` 同——概念要先铺垫才能被后段倚靠；prerequisite vs introduced 是杠杆。

**对话感 = 倒转的拷问**：构思阶段问"你到底在注意什么"，这里问"这篇文章到底在论证什么、读者该按什么顺序听？"顶回去，不让弱过渡蒙混过关。常用话术："这段给读者做了上一段没做的什么？""砍了它什么会坏？""这是散文还是该是列表？为什么？"

**形式的取舍要摆出来**：散文承载论证 vs 列表承载平行项；行内 vs callout（`> [!TIP]` 只在会真的打断主线时用）；表格 vs 重复结构（同构重复 3 次以上用表）；引 vs 述（原句是重点才引）；代码块 vs 行内（多行/可跑/示例→块，单 token→行内）。

**素材堆是采石场，不是剧本**：碎片可以拆、并、改写、跨段放，目标是读成同一种声音；缺料要明说缺口（"这里要个例子但堆里没有——现在给我一个或我们砍这段"）。

## 4. 一次典型运转

1. 通读素材。
2. 定 prerequisite。
3. 3 个候选开头，用户选。
4. 逐段：问下一步听什么、取料、争形式、append。
5. 到用户满意为止。

**写作节奏**：每段同意就 append；写前重读文件；要改某段就原地改、其余不动。

## 5. 何时用 / 何时不用

**用**：有一份 raw material 要逐段成文时。

**不用**：
- 挖掘新碎片（`writing-fragments`）。
- 改 raw material 文件（本 skill 明确 read-only）。
- 发布/平台格式化/加 frontmatter（out of scope）。

## 6. 依赖与网络位置

- 是 mattpocock"写作三件套" exploit 的一支。
- 与 `writing-beats` 同属 exploit，但单位是"段"而非"拍"。

## 7. 易错点与坑

- **跳过形式争论**：每段形式要刻意选择，不是默认散文。
- **跳用未铺垫概念**：同 `writing-beats`，先铺垫再倚靠。
- **批量写**：要边写边 append，让用户看着文章成形。
- **动 raw material**：它是 read-only，别编辑。
