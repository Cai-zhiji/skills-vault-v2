# grilling

> 对计划、决定或想法做无休止的拷问，直到达成共同理解——把讨论映射成一棵"设计树"，逐轮推进。

## 1. 一句话理解

`grilling` 是整个 mattpocock 技能集的**底层对话原语**：把一次模糊的讨论，组织成对"设计树"的系统遍历——每个决定分叉出挂在它下面的决定，一轮问完当前所有可问的问题。

## 2. 它解决什么问题

模糊的计划/决定/想法，最常见的死法是**跳着问、猜着答**——要么问了依赖还没答案的问题，要么漏掉关键分支。`grilling` 用"前沿（frontier）"这个概念根治：只问前置条件已定的问题，一轮全问完，等你答完再重算前沿。

## 3. 核心心智模型

**设计树 + 前沿。** 每个决定是一条分支，每个决定的前置都定了，它才"可问"；所有当前可问的决定构成**前沿**，一轮全部问出。每轮回答重塑树——已定的决定把前沿往外推，解锁依赖它的新问题。

两个硬约束：

- **查事实是你的活，不是用户的。** 前沿问题需要环境事实（文件系统、工具）时，派子 agent 去查，别问用户你能自己查到的东西。子 agent 在跑 = 一个未定的前置，只有依赖它的问题等它，其余前沿照问。
- **决定是用户的。** 每个问题附你的推荐答案（`➡️`），但最终选择归用户。

会话结束的标志：**前沿为空**——每个分支都访问过，没有静默假设。达成共同理解前不动手。

## 4. 一次典型运转

1. 识别主题，把已知事实先查清。
2. 算当前前沿，一轮编号问出所有问题，每个附推荐答案。
3. 等用户答完，重算前沿，问下一轮。
4. 前沿空 → 宣布共同理解达成 → 停。

## 5. 何时用 / 何时不用

**用**：想压力测试思路、或用任何"grill"触发词时。

**不用**：已经明确、只需执行的任务。

## 6. 依赖与网络位置

- 是 `grill-me`、`grill-with-docs`、`loop-me`、`triage`、`wayfinder` 等的底层原语。
- 常与 `domain-modeling` 合跑（边问边固化术语）。

## 7. 易错点与坑

- **问依赖还没答案的问题**：那是下一轮的事，别这轮问。
- **把查事实丢给用户**：能自己查的（文件、工具、环境）就派子 agent。
- **不附推荐答案**：每个问题都要给 `➡️` 推荐，帮用户低门槛回答。
