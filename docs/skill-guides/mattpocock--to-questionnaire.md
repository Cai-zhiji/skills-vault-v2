# to-questionnaire

> 把一个你无法独立回答的决定，变成一份问卷，交给别人异步填（或会上一起填）。

## 1. 一句话理解

`to-questionnaire` 产出一份 **discovery 问卷**（Markdown 文档）：接收者掌握你所缺的知识，问卷把它从对方那里"拉"出来。关键做法是**拷问"发送"，不拷问"主题"**——只问你能回答的：发给谁、需要对方回什么。

## 2. 它解决什么问题

有些决定卡在"你缺的信息在别人脑子里"。与其反复猜，不如把"gap"结构化成一份问卷。区别在于：访谈你只问发送的元信息（对方是谁、你需要什么回来），问题本身瞄准"对方知道的 vs 你需要的"之间的缺口。

## 3. 核心心智模型

**三步，前两步各一次交换：**

1. **发给谁？** 一次问清对方的角色、专长、与你的关系——这决定语气和要带多少上下文。
2. **需要回什么？** 一次问清你无法独自解决、需要对方给的具体决定/事实——产出你"走时必须能做的事"清单。
3. **写问卷**：瞄准 1–2 的缺口，按文档结构，写到 `to-questionnaire-<slug>.md`。

**文档结构**：Purpose / From-To-用途 / Context（一段，帮没进你脑子的人） / How to answer（截止+工作量，明说"部分答案和不知道也有用"）/ 按主题分 `##` 节 / 每个问题一个想法（不复合）+ 答案桩 + 仅在易误解时加一行"为什么重要" / 结尾 Anything else。

**最重要的问题排前面**——异步场景你可能只有一次机会拿到回复。

## 4. 一次典型运转

用户说"我需要架构师定夺选型"：

1. 问：对方是谁、专长、关系（一次）。
2. 问：你具体需要他拍板/给什么（一次）。
3. 写问卷：问题瞄准缺口，最重要在前，按主题分组，写到文件并报路径。

## 5. 何时用 / 何时不用

**用**：有个决定你答不了、得靠别人（异步或会上）。

**不用**：你自己能查到的信息（那该用 `research`）；对方就是你自己的话（拷问该用 `grilling`）。

## 6. 依赖与网络位置

- 是 `ask-matt` 的独立任务入口之一。
- 与 `grilling`（问自己）相对——它问的是"外面的人"。

## 7. 易错点与坑

- **拷问主题而非发送**：你会问出你本答不了的问题——只问"发给谁 + 要回什么"。
- **复合问题**：每个问题一个想法，别一句话塞两个。
- **重要问题埋后面**：异步只有一次机会，最重要的放最前。
