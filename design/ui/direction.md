# Skills Vault v2 界面方向

## 设计命题

对象是维护多个来源、多个平台 Agent Skills 的本地开发者。页面的单一核心任务不是展示数量，而是让用户看懂“文件、Catalog、选择与实际安装是否一致”，并安全消除不一致。

## 参考如何使用

- Linear：借鉴紧凑的信息层级、细分隔线和克制的强调色。
- Raycast：借鉴命令面板、键盘路径和工具界面的直接反馈。
- Vercel：借鉴技术信息、路径、状态与错误的清晰排版。
- Cursor：仅借鉴把阶段状态编码进真实流程的方式，不采用其暖米色营销外观。

参考资料只用于分析原则；不复制品牌色、专有字体、插图或营销页面结构。

## 视觉语言：Repository Workbench

界面像一张本地仓库工作台：冷静、可检查、能追踪。它不是 SaaS 数据看板，不使用四张大统计卡、装饰渐变或宣传型 hero。

### 色彩令牌

| 名称 | 色值 | 用途 |
|---|---:|---|
| `bench` | `#E8EBE7` | 页面底色，冷铝灰工作面 |
| `surface` | `#F7F8F5` | 列表、侧栏与操作面 |
| `graphite` | `#1E2933` | 主文字、边框与高对比操作 |
| `copper` | `#C45F3C` | 当前选择、主要动作与运行节点 |
| `safe` | `#287A58` | 已同步、成功和安全状态 |
| `fault` | `#A6404C` | 阻塞、失败与危险动作 |

颜色必须与文字和图标一起表达状态，不能成为唯一线索。深色模式后续从同一语义令牌派生，不在首轮用“全黑 + 亮色”取代品牌思考。

### 字体角色

- 状态标题与小节标签：`Barlow Condensed`，只用于短标签、计数和操作阶段，形成设备铭牌感。
- 中文正文与控件：`Inter`, `PingFang SC`, system-ui，14px 基线。
- 路径、commit、时间和技术状态：`JetBrains Mono`, `SFMono-Regular`, monospace。

如果字体无法本地随应用分发，优先保证中文与数据可读性，不依赖运行时网络字体。

### 几何与密度

- 4 / 8 / 12 / 16 / 24 / 32 的间距阶梯。
- 6px 为默认控件圆角，10px 只用于 Sheet、Dialog 和命令面板。
- 以 1px 分隔线建立层级，阴影只用于浮层。
- 列表行 48–56px；正文最小 12px；可点击区域至少 40px。

## 布局假设

桌面采用不对称三栏，中央列表承担主要阅读，右侧只保留同步状态或当前操作上下文。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ Skills Vault   workspace / local       ⌘K              [扫描本地]  │
├──────────────┬─────────────────────────────────┬────────────────────┤
│ Skills       │ 搜索、筛选、批量上下文          │ 同步轨 / 当前操作  │
│ 来源         │ ──────────────────────────────  │                    │
│ 记录         │ Skill / Source / Record rows    │ files ● catalog ○ │
│              │                                 │       ├ Codex ●    │
│              │                                 │       └ Claude ●   │
├──────────────┴─────────────────────────────────┴────────────────────┤
│ 持续错误或最近完成的操作；没有后续动作时才使用 toast               │
└─────────────────────────────────────────────────────────────────────┘
```

建议起始宽度：左栏 216px，中央最小 560px，右栏 312px。具体断点在原型票据中验证。

窄屏把一级导航变为顶部切换，同步轨折叠为主内容上方状态带，详情 Sheet 占满视口；关键操作状态不能因侧栏消失而不可见。

## 签名元素：同步轨

```text
本地文件 ── Catalog ──┬── Codex
                      └── Claude Code
```

每个节点使用统一状态词：`已同步 / 待扫描 / 待安装 / 被阻塞 / 运行中`。只有当前运行节点出现短距离脉冲；减少动态效果模式下改为静态描边。

同步轨既是状态摘要，也是导航：激活节点把中央区域切到对应的待处理对象，但不直接执行破坏性动作。

## 组件策略

使用 shadcn/ui 的行为原语，不沿用默认展示外观：

- `Command`：全局搜索、导航和安全动作入口。
- `Sheet`：Skill、来源与事务详情。
- `Dialog` / `AlertDialog`：批量、恢复、删除和实际 Apply 确认。
- `Table` 或语义列表：高密度对象浏览；移动端转换为分组行而非营销卡片。
- `Tabs`：只用于同一对象的平级视图，不承担一级导航。
- `Toast`：仅用于无需后续处理的短成功信息。
- 自定义 `OperationRail`：持续展示阶段、错误与恢复动作。
- 自定义 `SyncRail`：展示领域同步关系。

## 文案规则

- 控件用用户认识的动作：`扫描本地 Skills`、`保存选择`、`预览安装`、`应用更新`。
- 同一动作从按钮到结果保持同一个动词。
- 错误说明原因、未发生的改变和下一步，不只显示状态码。
- 空状态邀请执行一个明确动作，不使用宣传语。

## 自我审查

第一直觉是套用 shadcn 的 Sidebar + 卡片 Dashboard，这会让文件、Catalog 和平台链接看起来像任意 SaaS 指标。现方案移除营销 hero 和统计卡矩阵，把视觉风险集中在同步轨；其余界面使用克制的工作台分区和数据行。这样既保留 React 组件效率，又让结构来自 Skills Vault 的真实领域关系。

在原型阶段必须验证：三栏是否过密、同步轨是否真的减少理解成本、Barlow Condensed 是否影响中文混排，以及铜色主动作在浅色与深色模式下的对比度。
